# Specification collaboration

Specification changes require agreement before editing.

1. Discuss one bounded piece at a time.
2. Identify what the existing specification already decides and what still needs the user's input. Distinguish existing behavior being documented from proposed new behavior requiring a decision.
3. Propose the exact change, including any new behavioral decisions.
4. Wait for explicit approval before editing.
5. Edit only the agreed piece, report the changes, and stop. Approval applies only to that piece, not to the rest of the specification.

“Continue” authorizes the next discussion, not drafting the remaining specification.

A correction that reveals a mistaken assumption requires stopping and rechecking the approach with the user, not immediately patching the document.

Questions are not edit requests.

Do not fill gaps in understanding with invented requirements. Investigate existing behavior and ask about unresolved decisions before proposing changes.
